# concept-snap · 概念快照

> 给它一个概念，还你一页能用的速览卡：是什么、为什么有它、什么时候用、会怎么考 / 怎么问。

一个 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 技能（skill）。不是百科条目，是一张**能立刻拿去用**的卡片。

## 它解决什么

查一个陌生概念，通常只有两种结果：百科给你三千字定义，搜索结果给你十篇互相矛盾的文章。

concept-snap 的前提是：**概念几乎都是某个具体麻烦的补丁**。所以先讲清楚它补的是哪个洞——没有它之前人们怎么干、出了什么错——再讲它长什么样、什么时候该用、会以什么形式出现在题目和追问里。

## 一张卡长什么样

以「幸存者偏差」为例（默认档）：

> **一句话**：你只统计了活下来的那些，就以为没活下来的也一样。
> **精确版**：样本仅来自筛选后的存活子集，导致对总体分布的估计系统性偏离；偏差来源是"能否进入样本"与目标变量相关。
>
> **为什么有它**：没有它之前，人们拿"能观察到的样本"直接推断全体；而观察不到的那部分往往正是最关键的。它补上的固定追问是——"谁不在我的样本里，他们为什么不在了？"
>
> **什么时候用**：要从"成功者名单"总结成功原因时；数据只覆盖留存用户 / 返修产品 / 回访客户时；有人用"我认识的某某就这么干的"论证时；要评估真实失败率但失败记录没人上报时。
>
> **问题长什么样**：判断——这个结论有没有幸存者偏差；解释——为什么飞机要加固"没有弹孔"的部位；设计——怎么把缺失的那部分样本补回来。
>
> **原始案例**：二战盟军要给轰炸机加装甲，统计返航飞机的弹孔，集中在机翼和机尾，发动机和油箱几乎没有。直觉是"哪弹孔多加哪"，Abraham Wald 的结论相反：发动机中弹的飞机根本回不来，返航样本里当然看不到，该加固的正是没有弹孔的地方。**缺失的样本不是随机缺失的**——这就是这个概念的全部要害。
>
> *数字说明：不给具体百分比，原始报告的统计口径与机型不同，转述具体数字容易失真。*

## 安装

技能就是一组 Markdown，放进 DSH 的技能目录即可，不需要装插件。

**用户级（推荐，所有项目可用）**

```powershell
git clone https://github.com/<your-name>/concept-snap.git "$HOME/.dsh/skills/concept-snap"
```

macOS / Linux：

```bash
git clone https://github.com/<your-name>/concept-snap.git ~/.dsh/skills/concept-snap
```

**没有 git**：下载 ZIP → 解压 → 把目录重命名为 `concept-snap` → 放进 `~/.dsh/skills/`。

**确认装上**：新开一个对话，输入 `/concept-snap`，或者说一句"快速了解一下熵"。

> 目录结构必须是 `~/.dsh/skills/concept-snap/SKILL.md` 这一层，DSH 只扫描技能根目录的直属子目录，不做递归。

## 用法

三种触发方式：

| 方式 | 例子 |
|---|---|
| 斜杠命令 | `/concept-snap 什么是双下降` |
| 直接点名 | `用 concept-snap 讲讲边际效用` |
| 自然语言（靠 description 匹配） | `快速了解一下注意力机制` / `解释下幸存者偏差，我要讲给外行听` |

三档深度：

| 说法 | 档位 | 输出 |
|---|---|---|
| "一句话""快速""扫盲" | 极简 | 一句话、什么时候用、问题长什么样 |
| 默认 | 默认 | 四问 + 1–2 个按需块 |
| "讲透""面试要用""我要上台讲" | 展开 | 四问 + 全部相关按需块 |

## 卡片结构

**固定四问**（每张卡都有）

1. 一句话 + 精确版 + 所属领域（跨领域同名概念先给歧义提示）
2. 为什么有它：旧做法 → 旧做法的毛病 → 它补上了什么
3. 什么时候用：3–5 条"当你要 ___ 时"
4. 问题长什么样：A 题型表（计算 / 判断 / 解释 / 设计）+ B 高频追问

**按需四块**（看概念决定，宁缺毋滥）

5. 原始案例
6. 公式 / 关键结构
7. 易混对比
8. 常见误区

取舍标准写死在技能里：**删掉这段，读者会不会用错？会就留，不会就删。** 八节填满但每节一句空话，被明确列为反面清单。

## 案例只用真的

这是这个技能最较真的一条。

**来源优先级**

1. 该概念首次被提出 / 首次落地时的原始案例——教材原始插图、原始论文里的实验、历史事件。优先用它，因为它同时解释了"为什么会有这个概念"。
2. 现实中反复发生的真实场景——能说出场景、做法、后果。
3. **禁止**临时编的 toy 数据（"假设 5 个点""设 x = 1, 2, 3""某公司有 100 个用户"）。

**数字规则**：有可靠来源才写具体数字；没有就用"明显 / 量级 / 大一个数量级"这类描述，并说明为什么不给。为了生动编一个 AUC 或百分比，是最常见的翻车点。

**抽象概念**：数学、逻辑这类没有"事故案例"的概念，用它**首次被解决的那个具体问题**代替（测地、振动、分赌本、编码）。

**没有案例**：整节不写，说一句"这个概念没有广为人知的落地案例"，不硬凑。
